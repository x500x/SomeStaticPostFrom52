为什么需要坐标换算

给出具体例子：

  • 通过自动化截图元素保存的滑块缺口图片：

  • 图片大小为：696*270

  • 浏览器中显示的滑块缺口图片

  • 通过元素定位我们可以看到图片大小为：360*140

通过上面举例我们可以知道，浏览器中显示的滑块缺口图片大小和我们本地保存的滑块缺口图片大小不一样
从而引发了一个问题：当我们是识别保存下来的滑块缺口图片，得到 x 像素，然后使用这个 x 像素，去使用自动化的方式来拖动缺口就会造成拖过头
原因：因为两张图片的长度不一样，导致要滑动 x 像素是不一致的

解决方法

经过上面举例我们可以知道，我们本地滑块识别得到的举例是不能直接去到浏览器自动化拖动的

下面给出换算方法：

  • 缩放比例 = 696 / 360 = 1.9333
696：本地图片宽度        360：网页图片宽度
页面拖动距离 = 识别本地图片得到的x / 缩放比例
页面拖动距离 = 214.3 / 1.9333
页面拖动距离 ≈ 111

小结

  • 截图识别出来的 x 是图片里的位置，动作链需要的 x 是页面里的距离。图片宽度和页面宽度不一样时，必须先按比例换算。
